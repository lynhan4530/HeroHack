## Feature 1 — ☕ Instant Coffee (Remove Disorganized)

### What it does
After a battle or siege break, the player's party gets a "Disorganized" debuff that severely reduces map speed for several campaign hours. This button instantly removes that debuff.

### API (confirmed via reflection on v1.3.15)
```csharp
// Check if disorganized:
MobileParty.MainParty.IsDisorganized  // bool, read-only property

// Clear it:
MobileParty.MainParty.SetDisorganized(false);
```

### Implementation
**`PartyCheats.cs`** — add method:
```csharp
public static string RemoveDisorganized()
{
    var party = MobileParty.MainParty;
    if (party == null) return "No main party.";
    if (!party.IsDisorganized) return "Party is not disorganized.";
    party.SetDisorganized(false);
    return "Disorganized debuff removed!";
}
```

**`PartyTabVM.cs`** — add `ExecuteRemoveDisorganized()` calling `PartyCheats.RemoveDisorganized()` then `RefreshDisplay()`.

**`HeroHackPanel.xml`** — add a button row in the Party tab Actions section. Pattern:
```xml
<ButtonWidget WidthSizePolicy="Fixed" HeightSizePolicy="Fixed" SuggestedWidth="200" SuggestedHeight="30"
              Command.Click="ExecuteRemoveDisorganized" DoNotPassEventsToChildren="true" Brush="ButtonBrush2">
  <Children><TextWidget Text="☕ Remove Disorganized" .../></Children>
</ButtonWidget>
```

## Feature 2 — 🏰 Siege Breaker (Instant Siege Engine Build)

### What it does
If the player is currently besieging a settlement, instantly completes all siege preparation (camp + all engines): sets `PreparationProgress` to 1.0 and marks camp as ready.

### API (confirmed via reflection on v1.3.15)
```csharp
var camp = MobileParty.MainParty.BesiegerCamp;
// BesiegerCamp has:
//   float PreparationProgress  (get only — set via reflection or found setter)
//   bool IsPreparationComplete (get only)
//   bool IsReadyToBesiege      (get only)
//   SiegeEnginesContainer SiegeEngines
//   void SetPrebuiltSiegeEngines()   ← this method exists!
```

### Implementation Strategy
`SetPrebuiltSiegeEngines()` is the key — it's the game's own method for pre-building siege engines (used for scripted story missions). Use it to instantly complete the siege camp:

```csharp
public static string InstantSiege()
{
    var party = MobileParty.MainParty;
    if (party == null) return "No main party.";
    var camp = party.BesiegerCamp;
    if (camp == null) return "You are not currently besieging a settlement.";

    try
    {
        camp.SetPrebuiltSiegeEngines();
        return $"Siege camp instantly completed at {party.BesiegedSettlement?.Name}!";
    }
    catch (Exception ex)
    {
        return $"Siege instant failed: {ex.Message}";
    }
}
```

> **If `SetPrebuiltSiegeEngines()` doesn't fully complete the preparation**, fall back to setting `PreparationProgress` via reflection:
> ```csharp
> var field = typeof(BesiegerCamp).GetField("_preparationProgress",
>     BindingFlags.NonPublic | BindingFlags.Instance);
> field?.SetValue(camp, 1f);
> ```
> Check what internal fields exist — the AutoGenerated members visible in reflection (e.g. `AutoGeneratedGetMemberValue_*`) show the field names.

**Wire up** same as Feature 1 — method in `PartyCheats.cs`, `ExecuteInstantSiege()` in `PartyTabVM.cs`, button in XML.

## Feature 3 — 🛸 Teleportation

### What it does
A **settlement cycler** (`< Settlement Name >`) + **"Teleport"** button. Clicking Teleport instantly moves the player's party to the selected settlement's position with zero travel time. No click-on-map (that requires engine-level input hooks — too risky).

### API (confirmed via reflection on v1.3.15)
```csharp
// These all exist on MobileParty:
MobileParty.MainParty.Position         // CampaignVec2, get + set ✅
MobileParty.MainParty.SetPositionAfterMapChange(CampaignVec2 newPosition)  // safest setter

// Settlement position:
settlement.Position2D  // Vec2

// Convert Vec2 → CampaignVec2:
new CampaignVec2(vec2.X, vec2.Y)  // or cast — check if implicit cast exists
```

### Implementation
**`PartyCheats.cs`** — add:
```csharp
public static string TeleportToSettlement(Settlement target)
{
    var party = MobileParty.MainParty;
    if (party == null) return "No main party.";
    if (target == null) return "No target selected.";
    try
    {
        var pos = new CampaignVec2(target.Position2D.X, target.Position2D.Y);
        party.SetPositionAfterMapChange(pos);
        // Also clear path so party doesn't resume travel
        party.Ai.SetMoveGoToPoint(target.Position2D);
        return $"Teleported to {target.Name}!";
    }
    catch (Exception ex) { return $"Teleport failed: {ex.Message}"; }
}
```

**`PartyTabVM.cs`** — add:
```csharp
private List<Settlement> _teleportTargets = new List<Settlement>();
private int _teleportIndex = 0;
private string _teleportTargetText = "-- (load tab first) --";

public void RefreshTeleportList()
{
    _teleportTargets = Settlement.All
        .Where(s => s.IsTown || s.IsCastle || s.IsVillage)
        .OrderBy(s => s.Name.ToString())
        .ToList();
    _teleportIndex = 0;
    UpdateTeleportText();
}

private void UpdateTeleportText()
{
    _teleportTargetText = _teleportTargets.Count > 0
        ? $"{_teleportTargets[_teleportIndex].Name} ({_teleportIndex + 1}/{_teleportTargets.Count})"
        : "No settlements";
    OnPropertyChanged(nameof(TeleportTargetText));
}

[DataSourceProperty]
public string TeleportTargetText
{
    get => _teleportTargetText;
}

public void ExecutePrevTeleportTarget() { if (_teleportTargets.Count == 0) return; _teleportIndex = (_teleportIndex - 1 + _teleportTargets.Count) % _teleportTargets.Count; UpdateTeleportText(); }
public void ExecuteNextTeleportTarget() { if (_teleportTargets.Count == 0) return; _teleportIndex = (_teleportIndex + 1) % _teleportTargets.Count; UpdateTeleportText(); }
public void ExecuteTeleport()
{
    if (_teleportTargets.Count == 0) { _onStatusUpdate("No targets loaded."); return; }
    _onStatusUpdate(PartyCheats.TeleportToSettlement(_teleportTargets[_teleportIndex]));
}
```

Call `RefreshTeleportList()` inside `RefreshDisplay()` (first time only, check if list is empty).

**`HeroHackPanel.xml`** — add a Teleport section in the Party tab. Use the existing `< value >` cycler pattern (same as Culture selector or Party Cap):
```xml

    <ButtonWidget Command.Click="ExecuteTeleport" SuggestedWidth="80" ...>Go!</ButtonWidget>
  </Children>
</ListPanel>
```

## Important Gotchas

| API | Note |
|---|---|
| `SetDisorganized(bool)` | Non-public but accessible — verify with reflection if build fails |
| `SetPrebuiltSiegeEngines()` | May be `internal` — use reflection fallback if needed |
| `SetPositionAfterMapChange` | Preferred over `Position` setter — handles grid update |
| `CampaignVec2` constructor | Check if it takes `(float x, float y)` or wraps a `Vec2` |
| **No SliderWidget** | Use cycler buttons only — SliderWidget crashes campaign Gauntlet |
| **No `[HarmonyPatch]` for new patches** | Use manual `ApplyPatch(harmony)` pattern from Sprint B |
